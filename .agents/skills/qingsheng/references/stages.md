# 七阶段场景参考

这些标签帮助选择咨询重点，不是关系必须依次完成的流程。可以先确立关系再讨论亲密，也可以在初次见面后仍处于互相了解；编号不能替代双方当前意愿。阶段判断先遵守 `SKILL.md` 的证据规则，写回字段遵守 `references/user-context.md`。

| 标签 | 有依据的使用场景 | 当前重点 |
|---|---|---|
| 阶段1 开场破冰 | 刚认识，尚未建立持续交流 | 自我介绍或从真实共同背景开始，给对方回应空间 |
| 阶段2 建立好感 | 能相互交流，开始了解兴趣和生活 | 分享与提问相互搭配，观察是否双向投入 |
| 阶段3 关系升温 | 双方持续表达好感，愿意接住彼此的轻度暧昧 | 真诚表达兴趣，确认两人都舒服 |
| 阶段4 邀约见面 | 正在提出或协调见面 | 分清未答复、婉拒、接受和已确认安排 |
| 阶段5 约会实战 | 已实际约会，或用户咨询即将到来的约会 | 关注相处体验、双方节奏和后续意愿 |
| 阶段6 亲密升级 | 双方明确愿意讨论或进行某项亲密互动 | 确认当前具体意愿，允许随时改变主意 |
| 阶段7 确立关系 | 正在沟通关系定义，或已双方确认 | 区分一方期待与共同确认，讨论实际相处需求 |

## 容易混淆的证据

- **深夜主动、秒回、问年龄收入、叫「哥」**：可能表示愿意交流、好奇或沟通习惯。结合多次互动判断，不能直接跳到邀约或约会。
- **说「改天吧」**：还没有落实见面。对方主动给替代日期时可以协调；没有替代安排时先留空间，不定时追问。
- **双方确认周六见面**：安排已确认，约会尚未发生。`state.stage` 不因此自动写 `dating`。
- **朋友聚会碰过面**：不一定是两人约会。首次相亲见面也不证明已有双向好感。
- **聊亲密话题、以前牵过手**：不等于当前同意身体接触；一次同意不涵盖其他行为。
- **一方说「我们算在一起了吧」**：这是确认请求；要看另一方明确回应，不能据此写 `partner`。
- **过去关系热络、现在明确拒绝**：按新的边界行动，保留历史事实，不让旧标签压过现状。

## 各场景的行动参考

### 开场与了解

从实际认识渠道、共同话题或对方明确分享的内容接话。直接介绍自己、问骑行路线、聊工作都可以；无需贬低、冷读性格或虚构见闻。她愿意展开时再顺着问，回应变短或表示累时自然收尾。

### 表达好感

表达自己真实的感受，比如在用户确实觉得聊得开心时说「跟你聊天挺开心的」。双方已经有共同玩笑时可以轻松调侃，不为了产生张力故意冷落、比较或攻击外貌。

### 提出与协调邀约

建议一个具体活动，给对方选择和拒绝的空间。地点、时间须基于用户真实可行的安排；没查到活动时先提出类型。接受邀约后再确认细节，不以虚构的忙碌或「不来就没机会」促成决定。

### 约会与亲密

关注两个人都舒服的安排。可以直接问希望做什么或是否愿意牵手；对方说不、迟疑或回避时停止当前动作。不要拿相处时长、约会次数或「没推开」作为同意依据。

### 确认关系与结束

需要确认关系时明确表达意愿，让对方自由回答。没有准备好时不替她解释成默认同意。明确拒绝或分手时接受其决定；要求停止联系时不给追加收尾消息或重新联系倒计时。

可复制的虚构回复例子见 `references/examples-library.md`，按实际背景改写。
