# 关系修复与重新联系

`/挽回` 先判断当前是否适合联系，再决定要不要给消息。遵守 `SKILL.md` 的边界与 `references/user-context.md` 的档案协议；不论模式名称是什么，都可以建议停止。

## 先确认事实

区分普通冷场、一次争执、明确拒绝、分手或停止联系。核对谁发了最后一条、实际时间、对方有没有明确表达边界、用户是否已经反复联系。信息不足时说明未知，不推断对方一定有别人或在测试用户。

- **明确要求停止联系或已拉黑**：停止。不给收尾消息、重新联系倒计时，也不通过其他账号、共同朋友或制造偶遇继续接触。
- **明确拒绝发展关系或提出分手**：接受决定。尚未回应且对方未要求停止联系时，可以给一句简短接受；已经回应就不再重复。不把退出当成让她回头的技巧。
- **双方都愿意解决的争执**：承认具体问题，说明真实可做的调整，询问是否愿意谈。不要用冷处理代替道歉或解决问题。
- **普通冷场且没有拒绝**：结合平时节奏判断。单次慢回不说明没兴趣；连续单向联系时先停下，不设三天、七天或两周到点重发的任务。

## 何时可以拟重新联系的消息

用户仍希望联系、对方未拒绝接触，且有自然的共同话题或双方约定的后续事项时，可以建议一次简短消息。未知经历、活动、城市或日程不能编造；没有合适理由时允许不发。对方没有回应时不自动再换一句。

对方主动重新联系，才根据新的内容重新判断；一个回复不意味着已经愿意复合或亲密互动。是否复合要双方明确沟通。

## 虚构例子

**普通聊天中断后，对方主动回来**
她：这两天太忙了，刚缓过来。
→ 忙完就好，这两天辛苦了。
理由：回应她给出的信息，不索要解释，也不立刻要求见面。

**用户确实失约，双方仍愿意沟通**
背景：用户确认忘记了原定时间，并希望承担责任。
→ 上次失约是我的问题，对不起。你愿意的话，我们找个时间聊聊。
理由：承认事实并留出选择，不用故意冷落替代解决问题。

**她提出分手，用户还没回应**
她：我觉得我们不合适，分手吧。
→ 我明白了，尊重你的决定。
理由：接受明确决定，不施压，也不承诺以后继续追求。

**她要求不要再联系**
→ 行动：停止联系，不再发消息。
理由：给出行动即可，不为了满足格式硬塞一条可发话术。

## 亲密互动的边界

过去的伴侣关系、亲密经历或当前聊天热络都不能替代此刻意愿。对方说「今天不行」「不想」或表现退缩时停止当前互动；不把口头拒绝解释为象征性抵抗，不在几分钟后自动继续。
