# 自动模式：草稿与条件分支

`/自动` 为用户生成可审核的聊天草稿和后续分支，不执行发送。先遵守 `SKILL.md` 的证据与边界规则，并按 `references/user-context.md` 加载当前对象；模式名不会扩大写档案或发送消息的授权。

## 输出格式

根据现在合适的行动，第一行可以是：

```text
[发送] 可直接复制的消息草稿
[等她回复] 当前消息尚未得到回应
[观察] 暂时不发，留意后续是否有主动联系
[停止] 对方要求停止联系，不再追加消息
```

- 只在适合发消息时使用 `[发送]`；消息中不夹 Markdown、动作或策略注释。
- 有明确的日程安排时可标 `[等待 具体时机]`；不为了模拟真人硬凑分钟数，也不设置未回复后的循环追发。
- 分支按对方实际回应的含义来写，不按字数或 emoji 数量判兴趣。只有收到新消息后才能选择分支。
- 已经说不方便、尚未答应或要求停止时，暂停相应邀约/互动。亲密话题不自动表示同意亲密行为。

## 示例：协调一次邀约

虚构背景：双方有意喝咖啡，用户已确认周日下午有空。

```text
[发送] 周日下午一起喝杯咖啡怎么样？
[等她回复]

如果她接受或提出替代时间：
  [观察] 先核对用户日程，再拟具体安排供用户确认。

如果她说不方便且没有替代安排：
  [发送] 好，那这次先不约。
  [观察] 不继续换方案催问。

如果她没有回复：
  [等她回复] 不自动补发消息。

如果她要求别再联系：
  [停止] 不发额外收尾消息。
```

## 节奏与暂停

回复速度参考两人真实习惯、当前忙闲和事情是否紧急；正常实时对话不必故意拖延。草稿通常 1–2 句，emoji 参考用户习惯，不强制加钩子或追问。

以下情形先暂停并说明缺口：对象身份不明、需要未知个人事实或未确认的日程承诺、对方表达不适或拒绝、用户准备发送重要情感承诺。已有事实足够时继续提供合适的草稿；不编造经历或替用户决定。

用户要求只读时不写档案；允许保存时把草稿标为「未确认执行」，不得追加到真实聊天记录。用户说 `/顾问` 时回到普通建议。
